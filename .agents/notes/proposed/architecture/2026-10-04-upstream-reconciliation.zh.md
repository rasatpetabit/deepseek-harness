# Agent Note: 固定上游版本协调与局域网 HTTPS

Status: proposed

[English](2026-10-04-upstream-reconciliation.md) | 中文

## Problem

车队分支需要已发布的 dsh-v0.2.1-alpha.1 运行时，同时保留局域网自动登录、远程设置管理、持久凭据以及可回滚的生产版本。主检出中的运维文档由操作员所有，本次升级不得包含、暂存或修改它。

## Proposal

将 dsh-v0.2.1-alpha.1 指向的不可变提交合并到仓库内的隔离工作树。按目标 API 解决上游文件冲突，仅保留有依据的内部行为，并提交候选更改；不推送，也不集成到 master。这符合仓库意图：上游拥有产品架构，内部差异负责车队运维。

已批准的设计回执为运行 bf5b55e1-45fd-4357-af18-09594f3bda04，审阅者为 gpt-6.1-sol，确切会话位于操作员指定的协调会话下的 c68eafac/run-0/session.jsonl。结论为允许实现的 PASS，不是激活许可。父会话负责实际服务模型证明、独立实现计划审阅及确切制品发布审阅。准备时尚无计划审阅回执。

## HTTPS and authentication

标准 nginx TLS 代理在 server 层仅允许 192.168.100.0/24，并对所有其他客户端统一拒绝，覆盖 HTTP 路径、资源、流和升级。后端绑定 127.0.0.1:3080。浏览器端地址为 https://192.168.100.200 ；nginx 拒绝其他 Host 值、任何非该精确 HTTPS 源的 Origin、不透明的 null 源以及跨站 Fetch Metadata。浏览器 WebSocket 升级要求精确 Origin。后端接收公共 Host；传入的转发头被移除，绝不提供身份。代理为 cookie 添加 Secure，关闭流缓冲，保留升级协议头，并让访问日志省略查询字符串及令牌。

仅在浏览器准入检查之后的干净 GET / 中保留现有 trustedNetworks cookie 交换。被接受的回环套接字表示可信代理跳点，而不是原始浏览器。API 调用仍须提供有效且绑定地址的签名 cookie。保留上游相对目录重定向、publicUrl 行为、持久签名密钥归属以及使用目标 ConfigForms API 的已认证远程管理。不得引入身份头解析器或其他密钥。

TLS 签发者选择及浏览器信任仍是未解决的投产工作。车队 Caddy 内部 CA 先例明确预期信任警告，不能证明客户端已信任。在确切制品发布审阅之前，不生成本地证书，不安装在线代理，不重启服务，也不激活生产。

## Immutable deployment source

部署脚本接收明确的规范路径、干净且已提交的源工作树和预期完整不可变 SHA。它在依赖安装及构建前后验证仓库身份、包含未跟踪文件的源清洁状态以及 HEAD，归档该确切 SHA，并仅从同一源覆盖构建输出。保留生产隔离及服务健康检查。错误仓库、脏源、移动的 HEAD 和源变更在提升版本前失败。绝不提交或 stash 主检出的更改来绕过干净源要求。

## Plugin and data verification

通过临时配置的运行时测试选择更新且兼容的已发布插件版本，而不只依赖声明的 peer 范围。已安装的 subscriptions 0.9.2 和 Hindsight 0.6.1 是基线；subscriptions 0.9.7 排除目标 peer，Hindsight 0.8.0 修复元数据。精确版本兼容豁免需要临时能力证据和独立审阅；禁止全局绕过和供应商代码编辑。

在复制的临时数据上使用受支持的目录迁移机制之前，盘点所有生产 Session 代及历史子会话。报告的 36 个 v3 日志需要在 v4 下完成读、写、重新打开验证，并保持前代哈希不变。比较全部七条路由的提供者、模型及推理力度身份，而不只比较基线数量：code 9/9、deepseek 1/1、LiteLLM 15/15。在生产之外恢复现有 restic 备份，包含配置、凭据、插件清单、锁文件及精确插件树；用匹配的旧运行时启动恢复的数据，不进行付费模型调用。报告绝不出现凭据内容。

## Alternatives considered

**仅手动令牌登录**违反局域网自动登录要求。**转发客户端身份或共享代理密钥**增加不必要的解析和凭据生命周期。**直接访问局域网后端**绕过 TLS 和统一边缘策略。**从脏主检出部署或归档移动的 HEAD**让版本脱离已审阅制品。**仅代码回滚**无法证明持久格式升级后的兼容性。

## Acceptance criteria

候选包含固定上游合并、有狭窄依据的冲突修复、认证拒绝测试、代理配置测试、不可变源部署测试、受影响的 README/JSDoc 更新以及决策记录。因合并改变已发布运行时路径，针对性提交检查包含构建和类型检查；默认不在本地运行穷尽测试。

激活前，独立审阅确切已提交制品，并证明各类路径的允许及拒绝客户端、自动登录和重新加载、无 cookie API 拒绝、错误 Host/Origin 拒绝、伪造转发头不提供身份、WebSocket Origin 强制、局域网后端拒绝、证书 IP SAN/证书链/有效期/客户端信任、实际消费的插件能力、完整迁移完整性、保留身份的目录比较以及匹配旧运行时恢复。

暂停写入者后，回滚一并恢复旧版本及其一致的数据、插件、设置、凭据、服务配置和边缘配置。保留前代日志不保证降级。生产绝不从开发工作树执行。

## Risks

七个预测合并冲突及插件兼容性仍是实现工作，不能假定成功。TLS 客户端信任、迁移完整性、恢复运行时证据及独立审阅是激活前提。本提案不授权与协调无关的工作流、安装器、供应商或执行框架核心修复。操作员所有的运维文件保持逐字节不变。
